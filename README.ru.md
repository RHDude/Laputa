# Laputa

**Личная панель серверов: приложение для Android, а сторож и агент — в одном файле на Python без зависимостей.**

[![Лицензия: GPL-3.0-or-later](https://img.shields.io/badge/license-GPL--3.0--or--later-blue.svg)](LICENSE)

![Python 3.8+](https://img.shields.io/badge/Python-3.8%2B-3776AB?logo=python&logoColor=white)

[English](README.md) · Русский

</div>

Laputa сообщает, когда умер сервер или служба, и почему: перезагрузка из панели, нехватка памяти, пропала связь, отключили свет в одном месте. Прямо из уведомления можно перезапустить службу или заглушить узел. Остальное, что нужно каждый день, — на экране узла: службы, контейнеры Docker, бэкапы, обновления, игровая консоль и свои кнопки действий.

## Что где

| Путь | Что это |
|---|---|
| `server/laputa.py` | Сторож и агент, один файл без зависимостей. Собирается из `server/parts/` |
| `android/` | Оболочка приложения: WebView, уведомления, виджет, фоновая проверка |
| `ui/` | Интерфейс приложения и словари на шести языках |
| `test/`, `tools/` | Проверки и стенд |

APK собирается из исходников (см. «Сборка»).

## Как устроено

- **Агент** стоит на каждом узле и работает от root. Раз в 10 секунд он сам отправляет сторожам метрики и состояние служб, поэтому входящие порты на узле не нужны: подходит и сервер за NAT.
- **Сторож** стоит на сервере с открытым портом и работает от отдельного пользователя без прав. Он решает, кто замолчал, ведёт журнал событий и отвечает приложению.
- **Приложение** знает только сторожей. Адресов узлов в нём нет, всё приходит по ключу.

Сторожей лучше два, на разных серверах. Тогда они отличают смерть узла от обрыва связи и сообщают о смерти друг друга.

Узел считается запаздывающим через 35 секунд без сигнала и молчащим через 75.

## Установка

Нужны Linux, Python 3.8 или новее и `openssl` на сервере сторожа. Службы видны там, где есть systemd, контейнеры — там, где есть Docker. Проверено на Debian, AlmaLinux и Alpine; обновления считаются для apt, dnf/yum, pacman, zypper и apk.

Сообщения сервера (вывод установщика, `status`, `keys`, журнал служб) — на русском или английском. Язык берётся из локали системы при установке или задаётся `--lang ru` / `--lang en` у `install-hub` и `install-agent`, и запоминается. Команда из `keys` передаёт язык сторожа новым узлам.

### 1. Первый сторож

Скопировать `server/laputa.py` на сервер в `/tmp/laputa.py` (например, `scp`).

**На сервере сторожа:**

```
sudo python3 /tmp/laputa.py install-hub --host ВНЕШНИЙ_АДРЕС --name ИМЯ --place МЕСТО --open-port
```

`--open-port` открывает порт 8743/tcp в ufw или firewalld. Без него откройте порт сами.

Команда напечатает ключ приложения (`laputa1:…`) и готовую команду для остальных узлов.

### 2. Остальные узлы

**На каждом узле** выполнить напечатанную команду, подставив имя и место:

```
curl -fsSk --pinnedpubkey 'sha256//…' https://АДРЕС:8743/i/…/laputa.py -o /tmp/laputa.py && sudo python3 /tmp/laputa.py install-agent --hub 'laputa1a:…' --lang ru --name ИМЯ --place МЕСТО
```

### 3. Второй сторож

**На втором сервере** (агент на нём уже стоит после шага 2, файл лежит в `/opt/laputa/`):

```
sudo python3 /opt/laputa/laputa.py install-hub --host ВНЕШНИЙ_АДРЕС --open-port
```

Его команду для узлов выполнить **на каждом узле, включая первого сторожа**. Агент добавит второго сторожа к первому и сохранит свои службы. Без этого каждый сторож следит только за собой, и его смерть никто не заметит.

### 4. Телефон

1. Установить собранный APK.
2. Вставить ключ приложения первого сторожа.
3. На главном экране разрешить уведомления и работу в фоне.
4. Ключ второго сторожа добавить в «Настройки», «Сторожа», «Добавить».

### 5. Службы

Открыть узел, в разделе «Службы» нажать «Добавить». Агент сам подберёт, за чем стоит следить, и объяснит почему: слушает порт, свой юнит в `/etc/systemd/system`, падала, известная программа, контейнер Docker. Рекомендованные уже отмечены, остаётся нажать «Добавить». Название, тип и ссылку можно поменять потом в карточке службы, «Изменить ярлык».

Службы, которые появились позже и проработали больше часа, панель тихо предложит на экране узла: «Следить» или «Не предлагать».

## Что ещё есть на экране узла

- **Действия.** Свои кнопки задаются только на самом сервере, в `/etc/laputa/actions.ini`. Приложение их показывает и запускает, но создать не может. Пример лежит в самом файле:

  ```
  [Обновить бота]
  command = cd /opt/mybot && git pull && systemctl restart mybot
  service = mybot.service   ; кнопка появится и в карточке этой службы
  confirm = yes             ; спросить перед запуском
  timeout = 120             ; секунд, не больше 600
  user = mybot              ; от кого запускать, по умолчанию root
  ```

  Файл перечитывается сам, перезапускать агент не нужно.

- **Игровая консоль.** Появляется, если на узле есть служба с типом «Игра». Для Minecraft видны игроки, для любой другой игры с RCON — только консоль. Свои кнопки команд («+» под консолью) хранятся на узле.
- **Бэкапы.** «Следить за бэкапами»: агент находит папки с копиями, таймеры и cron, похожие на бэкапы. Как часто появляются копии, панель узнаёт сама; если очередная опоздает вдвое, придёт предупреждение.
- **Обслуживание.** Сколько обновлений ждёт, из них безопасности, и просит ли узел перезагрузку.
- **Перезагрузка.** Перед ней видно, кого она заденет: игроков, соединения со службами, активных пиров AmneziaWG и WireGuard. Варианты: сейчас; с предупреждением игрокам за 5 минут и за минуту; когда на узле никого не останется (ждёт до 24 часов, потом отказывается и пишет об этом). Перед перезапуском службы, к которой кто-то подключён, панель тоже спросит.
- **Если узел перезагрузился сам**, после возвращения на экране будет причина из журнала прошлой загрузки (нехватка памяти, паника ядра, зависание, обрыв без записей), последние записи и графики за 30 минут до падения. Если узел вернулся без перезагрузки, событие скажет, что пропадала связь, а не сервер. Службы, которые работали до перезагрузки и не поднялись после, дадут тревогу.
- **Если узел молчит**, соседние узлы проверяют его пингом, портом SSH и трассировкой. Кнопка «Текст для хостера» собирает письмо с результатами. Если замолчали все узлы одного места, придёт одна тревога с догадкой, что там пропал свет или интернет.

## Приложение

- Языки: русский, английский, украинский, немецкий, испанский, китайский. «Настройки», «Язык»; по умолчанию как в системе. Уведомления и ошибки сервера тоже на выбранном языке.
- Виджет на рабочий стол: одна строка о состоянии узлов. Обновляется после каждой проверки.
- В уведомлении о беде есть кнопки «Перезапустить» (для упавшей службы, на Android 12 и новее только с разблокированного телефона) и «Заглушить на час».
- Вход по SSH с адреса, которого узел ещё не видел, даёт предупреждение. Входы с известных адресов записываются в события без звука.
- Темы: Системная, Ночь, День, Сумерки, Океан, Чёрная (AMOLED), Рассвет, Мята. На Android 12 и новее ещё Monet dark и Monet light: цвета из обоев телефона.
- Службы на экране узла и во вкладке «Службы» свёрнуты по типам, если их больше шести. Группа, где что-то не работает, всегда открыта.
- Во вкладке «События» фильтр по виду событий и по узлам и поиск. Фильтр запоминается.
- «Настройки», «Что присылать»: для каждого вида событий (связь с узлами, службы, диск, бэкапы, входы по SSH, перезагрузки) — со звуком, тихо или не присылать вовсе, только писать в «События». На экране узла, «Уведомления по узлу», то же можно переопределить для одного узла. Настройки хранятся в телефоне, у каждого пользователя приложения свои.
- После нажатия «Перезагрузить» узел помечается синей мигающей лампочкой и надписью «Перезагружается», пока не вернётся. Службы, которые гаснут при перезагрузке, тревог не дают.
- Больше 8 узлов небо рисует в два яруса, больше 16 — по острову на место с числом узлов; узлы с бедой остаются отдельными островами.

## Тревоги

| Событие | Канал |
|---|---|
| Узел молчит, упала служба | Тревоги, со звуком |
| Не поднялась служба после перезагрузки, замолчали все узлы одного места | Тревоги, со звуком |
| Кончается диск (90 %), службу остановили мимо панели, служба постоянно перезапускается, сторож не работает, сторожа недоступны 3 минуты, бэкапы опаздывают, вход по SSH с нового адреса, узел так и не опустел для перезагрузки | Предупреждения |
| Узел или служба вернулись | Отбой, без звука, заменяет прежнюю тревогу |

В режиме «Сразу» приложение держит открытое соединение со сторожем и узнаёт о событии за секунды. В режиме «Раз в 15 минут» оно просыпается по расписанию. Проверка по расписанию работает в обоих режимах как страховка.

Перезагрузка узла из панели глушит тревоги по нему на 10 минут. Остановка службы из панели тревогой не считается.

## Обслуживание

**На сервере:**

```
sudo python3 /opt/laputa/laputa.py status      # что видит сторож или каким сторожам отчитывается агент
sudo python3 /opt/laputa/laputa.py keys        # показать ключи ещё раз
sudo python3 /opt/laputa/laputa.py rekey       # новый ключ приложения, если телефон потерян
sudo python3 /opt/laputa/laputa.py uninstall   # убрать Laputa с сервера
journalctl -u laputa-hub -u laputa-agent -n 50
```

Обновление: положить новый `laputa.py` в `/tmp` и либо повторить ту же команду `install-hub` или `install-agent`, либо заменить файл и перезапустить:

```
sudo install -m 755 /tmp/laputa.py /opt/laputa/laputa.py && sudo systemctl restart 'laputa-*'
```

Ключи, службы и история сохраняются. Обновлять все серверы, сначала сторожей: команда для узлов из `keys` скачивает файл со сторожа. Установки до сервера 1.2 продолжают говорить по-русски.

Если приложение ведёт себя странно: «Настройки», «Журнал панели».

## Безопасность

- Соединения идут по TLS. Сертификат сторожа самоподписанный, его отпечаток зашит в ключ, и приложение с агентами сверяют именно его.
- Ключ приложения даёт полное управление: перезапуск и остановку служб из списка панели, перезагрузку узлов, команды в игровую консоль, запуск действий из `actions.ini`. Произвольных команд оболочки в протоколе нет: действие — это команда, которую владелец сам записал на сервере.
- Проверка с соседей стучится только по адресу молчащего узла, каким его видел сторож; локальные адреса отклоняются.
- У агентов свой ключ. Им можно только подать сигнал и забрать команды.
- После 20 неверных ключей с одного адреса сторож не отвечает ему 10 минут.
- Пароль RCON хранится только на узле, в `/etc/laputa/agent.json` с доступом для root. `actions.ini` создаётся с доступом только для root.

## Что проверено и что нет

Проверено автоматически:

- Сервер: 68 проверок версии 1.0 и 108 проверок возможностей 1.1–1.2 (Docker, подбор служб, действия, консоль, бэкапы, «кого заденет», все виды перезагрузки, разбор падения, сверка после загрузки, проверка с соседей, общая тревога по месту, обновления, входы по SSH, коды ошибок, язык сообщений сервера) на стенде из сторожей и агентов, под Python 3.8 и 3.13. Systemd, Docker, ss, awg, journalctl, ping, traceroute и apt на стенде подставные.
- Установщик: в официальных образах Debian 12, Debian 13, AlmaLinux 9 и Alpine 3.22; там же подсчёт обновлений apt, dnf и apk.
- Интерфейс: 34 проверки в Chromium против живого стенда и 15 через подставной мост Android-оболочки, включая смену языка.
- Логика тревог приложения: 38 проверок, тот же Java-код на обычной JVM против стенда, включая формы чисел на разных языках.
- Тексты 31 вида событий совпадают в интерфейсе и в уведомлениях на всех шести языках. Все словари полны.

Не проверено:

- Настоящие Docker, AmneziaWG и журнал прошлой загрузки; разбор причин падения проверен на образцах записей.
- Настоящий сервер Minecraft и другие игры с RCON.
- Подсчёт обновлений pacman и zypper (образов этих систем при проверке не было), ветки для ufw и firewalld.
- Переводы делал не носитель языка, кроме русского.

## Сборка

Собирается без Gradle, инструментами из репозитория Ubuntu 24.04 (`aapt android-sdk-platform-23 android-sdk-build-tools dalvik-exchange apksigner zipalign`) и Node.js:

```
cd ui && npm install && cd .. && android/build.sh
```

Доступны только встроенные API Android, компиляция идёт против SDK 23. Каналы уведомлений и запуск фоновой службы вызываются через рефлексию.

Ключ подписи в репозитории не хранится. Сборка ищет его в `keystore/` (или в папке из `LAPUTA_KEYSTORE`: `laputa.jks` и `pass.txt`), а если не находит, создаёт новый. APK, подписанный другим ключом, не встанет поверх установленного: сохраните свой ключ.

Сервер собирается из частей:

```
cd server/parts && cat p0_common.py p1_modules.py p2_agent.py p3_hub.py p9_http.py p9_install.py > ../laputa.py
```
